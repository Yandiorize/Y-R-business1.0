# IELTS 机考模拟器 — 补丁提示词 v8（v7 未通过 4 项 + 用户新增 4 项，共 8 项）

> 使用方法：在 WorkBuddy 同一个任务对话里分段粘贴（每段开头加一句“还没发完，先存着别动手”，最后一段发完再说“发完了，开始执行”）。
> 项目现状：纯前端静态站（源码在 /workspace/ielts-app/），数据存 localStorage。
> 前提：v7 已部分落地，以下项实测通过，**不要重做**：词性字号（词性已是独立小 pill、明显小于单词）、顶栏胶囊按钮（清空 / A+字号 / 主题）、计时器去嵌套、图标居中与 logo 对齐、阅读卡片清晰度（实色白底深色字）、退出弹窗（结束并返回红色可读、与取消同高）、品牌 Y-IELTS、导出按钮、真浅色。
> 本版共 8 项，修完统一重新发布。

## P-1 反馈卡片补例句

- 现状：练习页答错后反馈卡片有中文释义和“再听一遍”按钮、底部有已答统计，但三道题（controversial / abandon / demonstrate）的反馈卡片里都没有例句。
- 改法：答错后反馈卡片必须包含：中文释义 + 例句 + “再听一遍”按钮；例句只在答后出现，答前不剧透。
- 先查词条数据里有没有例句字段：有则渲染出来；如果该词条本身就没有例句数据，卡片不留空白位，在汇报里写明“该词条无例句数据”即可——**不许编造例句**。

## P-2 阅读容器宽度改到 96vw

- 现状：桌面端阅读容器只有约视口宽度的 82%，没达到 v7 要求的 96vw + 12–16px 左右边距；两栏高度已顶满，不要动。
- 改法：内容容器宽度改为 96vw 以上、左右边距 12–16px；超宽屏可设 1600px 上限防止行过长；手机（≤430px）布局不动。

## P-3 发音状态提示 + 修“暂无可用语音”误报

- 现状（两处问题）：
  1. 点喇叭确实能出声，但播放中没有任何文字状态，只靠按钮变蓝表示，用户无法确认是在播放还是失败；
  2. 设置区还挂着红字警告“当前设备暂无可用语音”，可实测明明能出声——语音可用性判断是错的。
- 改法：
  1. 播放状态必须有文字：播放中显示“播放中…”，失败显示“朗读失败，点我重试”，喇叭按钮始终可手动点；不许只用颜色变化表示状态；
  2. 语音可用性判断必须以 speechSynthesis.getVoices() 的实际结果 + voiceschanged 就绪为准：列表还在异步加载时不许提前下“无语音”结论；检测到有语音时，红字警告必须消失；真正无语音时才显示警告，并给出可操作提示；
  3. 重申禁令：发音链路（本地音频 → IndexedDB → 在线接口 → 系统 TTS）任何一级失败都必须有可见反馈，最终兜底必须走到系统 TTS 或明确提示无可用语音，不许静默没声。

## P-4 默写模式补发音入口（已证实缺失）

- 现状：拼写默写模式新题会自动读，但页面上只有输入框和提交按钮，没有重听按钮——听不清就没法重听，默写没法好好做。
- 改法：
  1. 默写页题目旁常驻一个大号喇叭按钮，可无限次手动重听；
  2. 再加一个“发音”开关：开 = 新题自动朗读，关 = 只手动点喇叭才读，默认开；
  3. 只读单词本身，不读词性、释义、标点；发音失败时按钮旁显示“朗读失败，点我重试”，不许静默没声。

## P-5 底部标签栏改矮、五个按钮稍大（用户 2026-10-21 新增）

- 现状：底部标签栏（阅读 / 听力 / 写作 / 单词 / 范文五个按钮）整体偏高，看着像一条厚“刘海”压在页面底部。
- 改法：
  1. 栏体改矮：压缩标签栏的上下内边距，整体高度缩短一档；
  2. 五个按钮同步稍大：图标与文字字号各放大一档（约 10%–15%），保持清晰可辨；
  3. 五个按钮等宽均匀分布，选中态样式不变；
- 约束：按钮触点不小于 40px；底部安全区 padding-bottom: env(safe-area-inset-bottom) 必须保留，不许 Home 指示条遮挡按钮；栏体改矮不许靠裁切图标或文字实现。

## P-6 底部标签栏做成透明液态玻璃（用户 2026-10-21 新增，接 P-5 同一处）

- 改法：底部标签栏栏体改成透明液态玻璃——半透明毛玻璃质感：backdrop-filter: blur + 适当饱和度，背景色透明度约 0.5–0.7（浅色下白底半透明、深色下深底半透明），页面内容从栏体下方透过来；保留细边框与圆角，与全站液态玻璃语言一致。
- 清晰约束：五个按钮的图标与文字在透明底上必须清晰可辨——用高对比色，选中态加深/加亮区分；内容滚动到栏体下方时按钮仍可辨认（必要时在栏体底部加一层极淡的渐变衬底，但不许改回实色）。
- 范围约束：透明只做在标签栏这一层装饰层；内容卡片仍按 v7 B-2 保持实色清晰，不许全站改回半透明发雾；P-5 的改矮 + 按钮放大 + 安全区留白同步保留。

## P-7 全站液态玻璃氛围再加强（用户 2026-10-21 新增）

- 改法：整个站点的液态玻璃感再多一点——顶栏、模块工具条、卡片、弹窗、按钮等更多表面改用半透明毛玻璃（backdrop-filter: blur + 透明度约 0.5–0.8，随深浅主题适配），与 P-6 的标签栏保持同一套玻璃语言（细边框、圆角、透光感）。
- 可读性底线（取代 v7 B-2 里“卡片必须实色”的严格写法，清晰要求本身不变）：玻璃只做在容器层，文字本身保持纯色高对比；正文、题号、提示文字对比度必须达标；同一区域不许两层以上半透明玻璃叠加；不许为了玻璃感牺牲可读性、回到发雾发灰。

## P-8 英译汉模式补发音按钮（用户 2026-10-21 新增）

- 现状：英译汉练习题（看英文单词选中文释义）题目旁没有发音按钮，无法听词发音。
- 改法：
  1. 每道英译汉题目的英文单词旁常驻一个喇叭按钮，点按朗读该单词（只读单词，不读词性、释义、选项）；
  2. 新题出现时自动朗读一遍，与 P-4 的“发音”开关联动：开关开则自动读，关则只手动点喇叭才读；
  3. 答错重读与反馈卡片“再听一遍”同步保留；发音失败时按钮旁显示“朗读失败，点我重试”，不许静默没声；
  4. 汉译英、拼写默写等其他模式同步检查一遍发音入口，不许顾此失彼。
- 验收：以英译汉模式实测为准——进英译汉做一题，题目旁必须有可点的喇叭按钮且点按出声。

## 防假落地规则（8 项通用，违反即为未完成）

1. 每一项汇报时必须写明：改了哪个文件 + 关键改动（类名 / 函数名 / 改动前后对比），只写“已完成 / 已修复”不算数；
2. 发布后必须用无痕窗口 / 新标签重新打开验证一遍，排除旧缓存假象；汇报里写明验证方式；
3. 发布时更新静态资源指纹或 service worker 缓存版本，确保用户刷新后拿到的是新版；
4. 如果某项因结构或数据原因确实做不了，必须明说原因和替代方案，不许报“已完成”。

## 全局约束

1. 每完成一项先自己实际点击/操作验证真的生效，再做下一项；禁止留下“有入口但点了没反应”的半成品；
2. 不引入后端、不引入登录、不接付费 API；数据继续走 localStorage；老数据要兼容迁移，不许让用户已有词库、作答记录丢失；
3. 不破坏 v7 已通过的项和液态玻璃视觉；手机版改动用媒体查询隔离，不许把桌面版改坏；
4. 声音最终以用户真机验收为准（开发环境能出声不代表用户设备能出声），汇报时写明语音匹配逻辑与失败提示，不要只写“已修复”；
5. 全部改完统一重新发布。最后只汇报一张表：编号 + 状态（修复 / 已有跳过）+ 自测结果 + 发布链接。不要长篇解释过程。
