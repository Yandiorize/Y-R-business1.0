# IELTS 机考模拟器 — 液态玻璃极端强化提示词（只调样式，不动功能）

> 使用方法：在 WorkBuddy 同一个任务对话里分段粘贴（每段开头加一句“还没发完，先存着别动手”，最后一段发完再说“发完了，开始执行”）。
> 项目现状：纯前端静态站（源码在 /workspace/ielts-app/），数据存 localStorage，液态玻璃 UI 已上线。
> 本份说明：本份**取代玻璃综合版的玻璃参数（更激进）**，只管样式、不动功能、数据、题库、发音逻辑。方向：把玻璃感推到极限——更透、更糊、光感更强、全站玻璃化。可与 v9 一起发（玻璃参数以本份为准）。

---

## 一、极端参数（全站统一）

### 铬层（顶栏、工具条、底部标签栏、悬浮按钮、弹窗标题栏）——推到最透

- backdrop-filter: blur(28–40px) + saturate(1.8–2.0)；
- 透明度：浅色下白底约 0.25–0.4，深色下深底约 0.2–0.35；页面内容、背景色块从玻璃下清晰透过来，滚动时流动感拉满；
- 边框：1px，浅色下白色约 0.6、深色下白色约 0.25；顶部一道 1–2px 高光边（亮度高于其他三边，模拟光从上方穿过玻璃边缘）。

### 容器层（内容卡片、文章卡片、题目卡片、练习卡片、反馈卡片、词库卡片、范文卡片、弹窗主体）——强透

- backdrop-filter: blur(20–32px) + saturate(1.6–1.8)；
- 透明度：浅色下白底约 0.5–0.65，深色下深底约 0.45–0.6；
- 边框与圆角：与铬层同一套（1px 细边框、同级圆角），用透明度差拉开层级。

### 背景层（景深来源，玻璃感的底子）

- 页面背景不再是平的单色/简单渐变：铺一层大面积柔和光斑/色块（浅色下浅蓝紫粉多色柔光、深色下深蓝紫微光），光斑本身带 blur(60–80px)，让所有玻璃层都有东西可透、可折射；
- 背景光斑固定不动（不跟随滚动），玻璃层滚动时透出背景的不同部分，形成前后景深。

## 二、全站玻璃化（一个表面都不许漏）

以下表面全部改成玻璃（铬层或容器层按上面分档），不许留实色孤岛：

- 顶栏、阅读工具条、计时器条、模块工具条、底部标签栏；
- 阅读文章卡片与题目卡片、题号格面板、划词高亮工具条；
- 写作题目区、编辑区、统计面板、衔接词统计条；
- 单词卡片、词库行、搜索框、筛选条、学习统计面板、今日待复习卡片、错词本面板；
- 练习卡片、选项卡片、反馈卡片、进度条轨道、底部统计条；
- 范文列表卡片、范文详情区、题目/范文切换条；
- 全部弹窗（退出确认、清空确认、交卷确认）主体与按钮、输入框、选择器。

## 三、光感与动效（玻璃像真玻璃的关键）

1. 边缘折射感：玻璃边缘做内外两圈微光——外侧 1px 高光、内侧 1px 极淡的内阴影，模拟光线穿过玻璃边缘的折射；
2. 顶部高光：所有玻璃层顶部边框亮度高于其他三边，光从上方来，全站一致；
3. 悬停/按下微光：按钮、选项卡片悬停时透明度 +0.05–0.1、高光略亮，过渡 200–300ms；按下时透明度 −0.05，有按压感；
4. 主题切换过渡：玻璃参数跟随主题平滑过渡约 300ms，不许生切；
5. 遵守 prefers-reduced-motion：减动效模式下取消一切玻璃过渡与悬停光流动画。

---

## 四、可读性底线（极端归极端，这三条不许破，否则就是糊不是玻璃）

1. 文字永远纯色：正文、题号、选项、按钮文字、统计数字不许加透明度；文字加一层极轻的文字阴影（浅色下白色微光、深色下黑色微影）托住对比度；
2. 长文区下限：阅读文章、范文正文、写作编辑区这类长文容器，透明度不低于 0.6（浅色）/ 0.55（深色）——再透长文就没法读，这条是唯一例外；
3. 不许两层以上半透明叠加：同一区域不许铬层玻璃上再叠容器层玻璃；玻璃栏下方滚动内容经过时，栏内图标文字仍可辨认（必要时栏底加一层极淡渐变衬底，但不许改回实色）。

## 五、逐表面验收清单（改完按表自查）

- 顶栏、工具条、标签栏：透到能看清下方内容流动，blur 与高光可见，按钮文字清晰；
- 阅读文章卡片与题目卡片：强透但正文锐利，背景光斑透过卡片隐约可见；
- 单词、练习、反馈、范文各卡片：同一套玻璃语言，无实色孤岛，词性 pill、选项、释义、例句、再听一遍按钮全部清晰；
- 弹窗：主体比卡片实一档，按钮文字跟随主题，两按钮同高对齐；
- 输入框与选择器：玻璃底 + 纯色文字，输入时文字清晰；
- 浅色与深色各完整走一遍：同一页面切主题，玻璃与文字在两套主题下都达标才算过。

## 六、防假落地规则

1. 每一处汇报时写明：改了哪个文件 + 玻璃参数（blur 值、透明度、边框、高光），只写“已强化玻璃”不算数；
2. 发布后必须用无痕窗口 / 新标签重新打开验证一遍，排除旧缓存假象；汇报里写明验证方式；
3. 发布时更新静态资源指纹或 service worker 缓存版本，确保用户刷新后拿到的是新版；
4. 只改样式：不许动功能逻辑、数据结构、题库、发音逻辑、本地存储；老数据必须完好；
5. 做不了的必须明说原因和替代方案，不许报“已完成”。
