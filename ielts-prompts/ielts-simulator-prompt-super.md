# Y-IELTS super 版 — WB 提示词

（用户定：下一个版本，名叫 super，必须大改。执行本提示词之前，先装 skills：见 wb-install-10-skills.md，装完再动手。）

## 0. 精髓（大改也不能动的五条）

1. 真题机考行为：剑桥 17 真题 + 机考规则（计时、交卷、回顾、Band），改的是壳和流程，不是考试本身。
2. 数字可信：计分、Band、按题型正确率、趋势必须对；数字不对，精髓就没了。
3. 本地私有无登录：纯前端、localStorage、数据只在用户设备上，不加账号、不加服务器。
4. 练-错-复闭环：练习 → 错题本/复习队列 → 单词间隔 → 再练，不是单次做题。
5. 五模块一站式：阅读/听力/写作/单词/范文全在一个壳里，首页即入口。

大改 = 第一眼像换了个产品，但上面五条一条都不能丢。丢了就是换产品，不是升级。

## 1. 必须大改的标准（验收红线）

- 第一眼像新产品：首页、模块页、考试页三处 before/after 对照，每处第一眼至少 3 处可见不同；显微级改动不算落地。
- 显著变化 + 超级改动：壳、密度、流程都动，不只换皮。
- 每个改动都要有 before/after（截图或自测数值），没有的不算落地。
- 本版不接受零改动交付，详见第 10 节强制改动规则。
- 本质变化的定义：结构变化，不是细节修复。本版以三个结构手术为验收核心，缺一个就不算大改：① 首页与学习区分离 + 首页重构（首页只留概览 + 进度 + 下一步，不再堆模块卡；五个模块收进独立的学习区（紧凑模块行 + 各模块页）；第一眼认不出是原来那个首页）；② 阅读着陆页重构（回顾与新做分离，旧成绩默认折叠，live 题目放最前面，第一眼不再是旧成绩表）；③ 考试壳统一（全站同一顶栏 + 考试胶囊第二行，交卷前回顾屏，计时升级：10 分钟变黄、5 分钟红闪、到时自动交卷）。
- 补丁流停止：本版期间不再单独发小补丁、玻璃补丁；小补丁四项、玻璃五项、P0-6 提纲全部并进本版（第 4、5 节），发这一个提示词就行。
- 激进程度：源码级（见 1.5 节）——改代码结构，不只调样式；DOM 结构必须变，重复实现必须删。

## 1.5 源码级激进改动（用户原话：改源码，激进点）

本版改的是源码，不是调样式。以下全部是必做项：

- 结构重写，不是样式覆盖：首页、阅读着陆页、考试页的 DOM 结构必须变（旧结构不得只改 class 名或覆盖样式冒充重构）；交付时附新旧结构对照（关键节点变化）。
- 组件统一：顶栏、底栏、模块卡、弹窗、题号导航、概览卡各只留一套实现；全站搜出重复实现并删掉，交付时列出删除清单（删了什么、原来在哪、现在统一到哪）。删后全站回归（四张表里验）。
- 设计 token 化：颜色、字阶、间距、圆角、阴影、动效曲线全部走 CSS 变量（设计系统）；抽查发现散写数值，该设计系统项按未落地计。
- 状态重写，不打补丁：单词循环、阅读计分、听力状态、设置保持、我的面板刷新，全部以单一事实来源重写；不得在旧逻辑上再贴补丁（旧逻辑的 bug 清单见第 4 节，重写后逐项回归）。旧数据迁移必须保记录：键 ielts.cbt.v1 不变，旧提交记录不受影响。
- 死代码清理：删掉不再被引用的历史层（旧版壳、旧版导航、旧版结果块实现、重复按钮逻辑）；删前列清单、删后回归；删错导致功能丢失按未交付计。
- 顺序：组件统一与死代码清理在第 0 阶段出图之后做（先画图，再动手）；激进验收：结构对照、删除清单、token 抽查三项缺一即为未交付（与第 10 节整版交付规则叠加）。

## 2. 先调 skills（全程约束，不是一次性口号）

- 全程：karpathy-guidelines（先想再写、简单优先、最小改动、目标驱动）+ ponytail（能复用不重写）。
- 设计：ui-ux-pro-max（出一套完整设计系统：颜色、字阶、间距、圆角、阴影、动效曲线，统一全站，不许各页各一套）。
- 性能：performance + core-web-vitals（先测后改：LCP ≤2.5s、INP ≤200ms、CLS <0.1；整页 <1.5MB、JS <300KB、CSS <100KB；改前改后各测一次，数字写进表）。
- 无障碍：accessibility（WCAG 2.2：44px 触靶、焦点可见、减动效、对比度、键盘/读屏）。
- 质量：web-quality-audit + best-practices（全量审一遍）；impeccable（交付前 detect 全过，不过不交付）。
- 文案：humanizer（用户可见文案去 AI 味，说人话）。
- 报告：i-have-adhd（结论 + 编号步骤 + 一个下一步）。
- 只做一次：archify（一张“现版 → super”架构对照页）；diagram-design（只在关键流程确实需要图时画，不为画而画）。
- 不调用：seo（工具页在分享链接后，不做公开页优化）、book-to-skill（没有书）。

## 3. 第 0 阶段：先画图再动手（不写代码，只交图和风险）

- graphify：给现版代码画代码图（模块、数据流、localStorage 键、关键函数关系）。
- ponytail-audit：按复用优先给出现版地图（哪些能直接复用、哪些必须重写、哪些是坑）。
- 交：代码图 + 复用地图 + 风险清单（最可能改崩的三处 + 对策）。用户确认后再进第 1 阶段。

## 4. 第 1 阶段：功能线先行（数字对、设置记得住、入口唯一）

先对一下现状（2026-10-24 13:53 实测，新构建，相对 11:50 变了很多）：下面标【已落地】的只做回归检查，不得重做（重做浪费且可能改崩）；标【仍未落地】的才是本阶段要修的；标【半落地】的只修未落地部分。

1. 【已落地，只验不重做】单词循环：每词计数实时动；轮次只计真实完成轮（0 答退出不算轮）；只留一个“再听一遍”；闪卡背面必须有英文词 + 喇叭 + 中文；统计不滞后；错词本做错后必须有词。回归标准就是这几条，逐条验。
2. 【半落地】阅读计分：顶部文案已改成“已交卷 0 / 40”，这部分不动；只修题型药丸 11/11/9/9（现仍是 16/11/4/9；Q27–31 按新分类重划：以题型为准，不是按题号顺序硬切；除此之外不改任何题目内容）；折叠导航顶部按钮点后能重新展开（已验过，保持）。
3. 【已落地，只验不重做】听力状态一致：原文播放前隐藏、交卷后回顾时给全；题源/重置每次访问都在；只留一个交卷按钮；首次打开是新鲜答题态（不是无交卷记录却已交卷/复习态）；重置后回到 0/10。
4. 【已落地，只验不重做】设置保持：玻璃滑杆刷新后保持（0% 刷新后仍是 0%，不得变回 50%）；主题刷新后保持；字号、发音偏好刷新后保持。
5. 【半落地】入口唯一：听力只留一个交卷按钮（已落地，保持）；单词开始入口空库时只有一个，但载入词后出现第二个（中间面板“开始练习” + 右侧栏“开始一轮练习”两个文案）——只修载入态：全程恰好一个开始按钮、一个文案、放在练习设置下方显眼处。
6. 【仍未落地，修】继续练习：跟上次交卷/真实进度，不跟上次访问；首页卡片显示“下一步 + 进度条 + 上次断点续练 / 重练错项”。

8. 【仍未落地，修】退出弹窗文案：已答的每词进度是即时保存的，只是不保存未完成轮次；文案不得再写“本轮进度不保存”误导，按实际行为重写。

## 5. 第 2 阶段：UI 线（设计系统 + 密度 + 三视口）
