## A. Skills 调用表（必做，先确认再动手）

开始前先确认你已安装以下 skills（用户已另发安装指令）：karpathy-guidelines、ponytail、ui-ux-pro-max、impeccable、performance、core-web-vitals、accessibility、web-quality-audit、best-practices、humanizer、i-have-adhd。缺哪个先装哪个；装不上的明说原因，不要谎称已装再动手。调用方式：按技能名调用你 skills 目录里的技能。

### A1 工作方式（全程约束，高于一切单项）

- karpathy-guidelines：动手前先想清楚（需求不明先列假设、不猜）；简单优先（最小实现，不加臆想功能）；只改必须改的（不动无关代码与样式）；以可验证目标收尾（每项附验收证据）。
- ponytail：先复用（现有代码 / 函数 / 样式能用就用，不重写）；按 7 步阶梯决策（要不要做 → 现成代码 → 标准库 → 平台原生 → 已装依赖 → 一行能写就一行 → 最后才写最小实现）；懒在解法上，不懒在校验、安全、无障碍上。

### A2 视觉 / 设计系统：ui-ux-pro-max

- 用它统一全站配色、字体、布局方案，执行 B 的 0.3 设计系统定标与 0.10 图形优化（强档）的工具。
- 验收：上报选用的风格、色板、字体搭配 + 图标三档尺寸；壳上文字与图标在浅色 / 深色下均清晰。

### A3 性能：performance + core-web-vitals（先测后改，改后再测）

- 先在发布链接上跑 PageSpeed（或等价实测），上报改前 LCP / INP / CLS；改后目标：LCP ≤2.5s、INP ≤200ms、CLS <0.1；预算：整页 <1.5MB、JS <300KB（压缩后）、CSS <100KB（压缩后）。
- 本站单文件、无外部引用，预算本就满足，重点是三处：INP（JS 重流程不阻塞主线程：32 题流程、图表绘制、彩带不卡手机；不每点一次全量重渲染；非关键工作延后）；CLS（结果区 / 图表 / 目录 / 提示动态注入不顶布局：图表容器定高、预留空间、不在已有内容上方插入）；LCP（首屏轻量，结果段 JS 延后）。
- 不要声称没测过的 Lighthouse 分数；用什么测的就写什么，测不到明说。

### A4 无障碍：accessibility（WCAG 2.2 清单，逐项打勾上报）

- 触控目标不小于 44px；focus-visible 可见；prefers-reduced-motion 生效（动画 kill-switch + 庆祝动画提前返回）；壳上与内容区文字对比度达标；键盘能走通全部交互（翻卡、按钮、导航）；读屏关键处有标签。

### A5 综合质检：web-quality-audit + best-practices

- web-quality-audit 按它的流程统揽一遍（性能 + 无障碍 + 最佳实践），先出问题清单再修。
- best-practices：安全 / 现代 API / 代码质量相关项，适用的做，不适用的写明原因。

### A6 打磨验收：impeccable（交付前必跑）

- 交付前跑 detect（59 条确定性规则），输出 JSON 与退出码；全部问题修完再发布。
- 验收：上报 detect 结果（通过 / 未通过 + 剩余项 + 修了什么）。

### A7 文案：humanizer

- 站内面向用户的文字（关于、更新日志、提示、空态、按钮文案）按它改一遍：删套话空话、含糊数字换具体数字、去程式化结构与过渡词，意思不变。

### A8 汇报格式：i-have-adhd

- 最终汇报第一行就是结论与可做事项、多步骤编号、最后只给一个具体下一步；不写客套开场，不写“还有别的吗”收尾。

### A9 本次不调用的 skills（明说原因，免得硬套）

- graphify：单文件静态页，不需要代码知识图谱。
- archify：本次不产架构图解。

## B. v18 十一件事（必做，大改版本体）

### 大改版总原则：上部极简、内容优先（高于各单项，单项与总原则冲突时以总原则为准）

- 学习模块页上部只保留最必要的元素（返回 / 标题 / 计时），其余全部收进抽屉、底部或可收起区域；顶部不得以多层卡片 / 药丸 / 工具条叠加遮挡学习内容；
- 内容区全屏优先：文章、题目、编辑器、听力句、范文正文占满主视野，上部 chrome 不得挤占、不得悬浮盖住学习内容；
- 界面不乱：同一页面只留一套导航（顶栏或底栏，不双份）；同一区域只留一层卡片（不嵌套）；状态信息（题数、计时、交卷）合并为一行，不铺多行。

### 对标：学为贵（刘洪波）web（2026-10-23 实地学习，v.guixue.com/ielts/，未登录可看）

- 学：顶栏薄（约 9% 视野）且不压内容；模考考试条 + 居中单卡片、无广告无侧栏无悬浮物；阅读左题右文各自独立滚动；一屏一主任务（选题→说明→答题→确认分步走）；计时 / End Test / 字数同在一考试条；提交前二次确认、空写作拦截、提交后就地展开答案不跳转；
- 不学：正题无题号导航盘 / Review 屏；模考 End Test 无分数页；写作 End Test 跳错误页；标题拼写错误、计时 00:00:00、进度全 60% 等粗糙处；
- 结论：我们的题号格 + Band + 分题型准确率是优势，保留，只修“挡视野”。

### 显著变化验收（全版适用）

- 本版所有改动必须在真机上一眼可见：打开新版，第一眼就要和旧版不一样（顶栏瘦身、内容全屏、首页仪表盘、玻璃胶囊栏、图标重绘，至少一眼能认出三处以上不同）；
- 每项汇报必须附改前 / 改后对比（截图或布局数值），只写“已优化”不算数；
- 显微镜级改动不算落地：只调 1–2px、只改颜色深浅、只改字重小档、用户在真机上看不出区别 = 该项未落地，滚入下一版，不硬凑“已完成”。

### 超级改动（换代，不是修修补补）

- 打开新版第一眼必须像换了一个产品（整体视觉、导航、首页、壳全部新），“至少三处不同”只是下限；
- 四条底线不动：品牌 Y-IELTS 不变；壳上文字与内容区可读性不动摇；答题内容区素面规则不变（玻璃只做壳）；老数据与 key ielts.cbt.v1 完好；
- 超级 ≠ 功能膨胀：不加新模块、不改计分、不改题库；超级体现在视觉、导航、布局与信息层级上；
- 验收：附整站改前改后对比（首页、模块页、考试页三组）；第一眼看不出换产品的 = 未落地。

### 0.1 顶栏重构（瘦身分层）

- 模块页顶栏三段：左品牌、中导航或计时、右只留复习 / 主题 / 我的三个入口；玻璃滑杆、字号、数据已在“我的”里，不再回顶栏；

- 考试页（阅读 / 听力）顶栏只留计时、交卷、题号导航；
- 验收：顶栏不再重叠 / 挤压；范文按钮不重叠、不截断；三按钮组居中。

### 0.2 首页真仪表盘

- 去掉“点击任意处进入”启动页：打开直接进首页，不多点一下；

- 一个“继续练习”主按钮（接上次模块 / 进度）；
- 模块页底部导航条（含首页入口）保留；
- 验收：打开即首页，无多余点击；五卡进度与“我的”数据一致；模块可经底部导航回首页。

### 0.3 液态玻璃（iOS 27 + Windows 毛玻璃，只做壳）+ 设计系统定标

- 风格定调：iOS 27 Liquid Glass 为主 + Windows 毛玻璃（Acrylic / Mica）做底子，两者融成一种玻璃，不另起一套；
- Windows 毛玻璃底子：backdrop blur + 微透 + 主题色 tint + 极淡噪点质感；层级按 Mica / Acrylic 分层：背景最糊、卡片次之、弹窗与悬浮栏最实但仍透；弹窗出现时下方页面加极淡遮罩 + 模糊；
- iOS 27 液态玻璃面上：栏体做成悬浮胶囊式（四周留边、大圆角、不贴边贴底）；每层玻璃 1px 细边框 + 顶部 1–2px 高光边，边缘锐利不发虚；多层结构（底色层 + 玻璃层 + 高光层），折射延续到边缘、不突然截断成实色；玻璃层 saturate 1.4–1.8、背景光斑稍浓；图标保持本色，不被背景透色带偏；默认档铬层约 0.55、容器层约 0.75，不许默认就拉到最透；主题切换、滑杆拖动过渡约 200–300ms；悬停透明度 +0.05–0.1、按下 −0.05；遵守 prefers-reduced-motion；
- 范围：玻璃只做“壳”——顶栏、底部栏、模块卡片、面板、弹窗；答题内容区保持素面高对比，不得用玻璃材质：阅读文章、写作编辑区、听力句子、范文正文一律素面；
- 硬约束：壳上玻璃文字必须可读——玻璃面板下加遮罩 / 渐变衬底，正文对比度在浅色 / 深色下均达标；文字永远纯色，不许加透明度；同一区域不许两层以上半透明叠加；写作提示、占位文字不得再偏淡；
- 设计标尺一次定：字重（正文不得用 thin / light，标题 / 导航 / 按钮用粗体，上报改前 / 改后数值）、字号、间距、按钮尺寸（触控目标不小于 44px）、圆角；
- 圆角框不嵌套：同一区域圆角框不许嵌套两层以上；所有模式左上角汇总区（卡片环 + 中间环 + 题数药丸环，三层套叠）全部减为单层——一张卡片，题数、计时、交卷直接排在里面，不再套环；
- 玻璃透明度滑杆保留可用（默认值 50 不变，中间档），拖动实时生效（CSS 变量统一控制）、存 localStorage、刷新与切换主题后保持；滑杆两端都要实测：拉到“清晰”端全站接近实色、处处可读，拉到“通透”端玻璃感明显；
- 验收：上报字重数值 + 壳上玻璃参数（blur 值、saturate、透明度、边框、高光）；浅色 / 深色下壳上文字均清晰；内容区素面、无玻璃材质；滑杆两端实测通过；玻璃栏下方滚动内容经过时栏内图标文字仍可辨认。

## C. 商业化拦路项修复（必修，卖之前必须清零）

### C1 单词学习循环（计数、轮次、重复按钮、背面音频、重叠、统计滞后）

- C1-1 每词“累计答对 / 答错”冻住：每词答对 / 答错计数必须随每次作答立即 +1（与已答、轮次正确率同一数据源、同一时机更新）。验收：任一词答对后其累计答对变 1，答错后累计答错变 1；连续作答累计递增。
- C1-2 轮次虚增：完成轮次只在真正完成一轮时 +1（答完本轮全部题目）；中途退出、切换模式不得 +1；趋势区只在完成轮次 ≥1 时出现。验收：开一轮答 1 题后完成轮次仍 0；答完一轮全部题目后变 1；中途退出、切换模式不涨。
- C1-3 答错无声扩轮（二选一，推荐前者）：(a) 轮次长度固定不变，答错的词进错词本 / 复习队列（已有机制），不扩轮；(b) 如保留重排，必须在扩轮发生的当刻屏上明示（例如“答错的词已加入本轮复习，本轮 +1 题”）。验收：答错后轮次要么仍 20 题，要么屏上有扩轮说明；不得无声变 21 题。
- C1-4 两个“再听一遍”：只留一个（保留反馈卡片内的，删下方的；或反之，统一只留一处）。验收：反馈态全屏只见一个再听一遍。
- C1-5 翻卡背面丢音频与英文词：背面同时显示英文词 + 喇叭按钮（与正面同一发音入口），再加中文与三档评价。验收：翻到背面能看到英文词、能点喇叭重听，不用翻回正面。
- C1-6 特大字号词与词性 pill 重叠：练习卡片内词与 pill 的排布在特大（4/4）字号下不得重叠（换行或间距兜底，以特大实测为准）。验收：特大下三词的 pill 与词尾字母无触碰、无遮挡。
- C1-7 总统计慢一步：总统计随每次作答立即更新，不得等到下一题。验收：连续答 2 题后统计立即为 50%、2 答。

### C2 阅读计分（题数、分类、死按钮）

- C2-1 顶部题数与总数对不上：顶部题数与页面总数统一为 40（已答 X/40），不得出现 0/10 与 40 并存。验收：顶部与页面同一总数 40，答 1 题后两处同步变 1/40。
- C2-2 分类 pill 分布错：Q27–31 题型归属改为匹配；修正后填空 11、判断 11、匹配 9、选择 9，总和 40。验收：四 pill 为 11/11/9/9；分题型正确率按修正后归属统计。
- C2-3 顶部题数按钮在题号格收起时点了没反应：收起状态下点顶部题数按钮必须展开题号格（或跳到题号格）。验收：收起时点按钮 → 格子展开可见。

### C3 听力（原文可见、回访丢控件）

- C3-1 播放前全文可见：播放前不显示完整原文；句子原文只在该句播放后（或交卷后回顾时）可见；播放前只显示题干 / 空格。验收：按播放前屏上读不到任何一句原文；播过的句子按规则可见；交卷后回顾可见。
- C3-2 题源 / 重置回访消失：题源选择与重置在每次访问都可见（修状态 / 显隐逻辑，不只首访）。验收：首次与回访均见题源与重置；重置可用（答 1 空后重置回 0/10）。

### C4 底部导航盖内容

- 现象：宽屏下固定底部导航盖住内容：单词“开始练习”按钮要滚动才露出来，范文最后一行卡片被截，阅读面板底边被遮。改法：内容区加底部留白（高度 ≥ 导航栏高 + 安全区），使所有可点内容与末行内容在不滚动到底时也不被导航栏遮住。验收：宽屏下单词开始练习按钮、范文末行卡片、阅读面板底边三处均完整可见、不被导航栏压住。

### C5 范文来源重复

- 范文详情来源写“Cambridge IELTS 17 Academic · Test Test 1 · Task 2”。改法：来源去重，写“Cambridge IELTS 17 Academic · Test 1 · Task 2”（全站同类来源行一并检查，不得再有 Test Test）。验收：首篇范文来源无重复；抽查其余范文来源行无重复。

### C6 其他剩余 FAIL（小项，一并修）

- C6-1 首页三按钮组缺口：首页顶栏只有“我的”一个按钮，从首页无主题 / 复习直达。改法：首页补齐主题 / 复习直达（或等价入口），使三按钮组在首页也可达。验收：首页可见主题与复习入口且可点。
- C6-2 清空词库后今日新学不同步：二选一且文案一致：(a) 清空词库同步清零今日新学；(b) 今日新学明确为当日累计、不随清库变，并在文案中说明。验收：清库后今日新学要么为 0，要么文案说明其为当日累计。
