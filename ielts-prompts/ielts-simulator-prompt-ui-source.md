# Y-IELTS UI 源码优化 — WB 提示词（调 skills，源码级）

（独立任务：全站 UI 源码优化。先装 skills：见 wb-install-10-skills.md，装完再动手。不要和 super 结构版、新页面优化混在同一个任务里发。）

## 0. 目标与关系（先说清边界，不重复做）

- 目标：调 UI skills，从源码层面优化全站 UI（不是调几个样式值）：设计 token 体系 + 玻璃材质系统 + 组件统一 + 底栏。极端：全站各页、两档主题、全部状态；最便宜可用模型（见第 6 节）。
- 关系：super 的结构/功能项（手术①②③、计分、题型分母、提纲、继续练习、我的面板）和新页面的翻转行/留言功能已落地（21:14 实测），不在本提示词里，只回归。本提示词接管的 UI 源码项：super 第 5 节的玻璃必做、新页面第 2 节的底栏——以本提示词的交付为准，不重复做。
- 边界：深色 palette token 重做（灰度太重那条）不在本提示词里（另有安排），本提示词只做玻璃材质本身（透光/高光）在浅色/深色两档下的呈现，不动深色 palette 数值体系。
- 基线：先确认基线是新版分离结构（首页无模块行、无日期 pill，底栏 4 项，学习区翻转行，留言板独立），直接重载看，不要用站内跳转看旧版；基线不对先报。

## 1. 调用的 skills（UI 专项，最好最适合）

- UI 系统：ui-ux-pro-max（全站设计系统：颜色、字阶、间距、圆角、阴影、动效曲线，各页不许各一套；token 体系归它）。
- UI 质感：frontend-design（玻璃材质、层级、视觉打磨——材质感归它）。
- 无障碍：accessibility（WCAG 2.2：对比度数值、44px 触靶、焦点可见、减动效、键盘路径）。
- 回归测试：webapp-testing（全站回归：各页打开、底导航 4 项、学习区 5 行、留言表单、弹窗/抽屉、三视口；改动不得改崩功能）。
- 量化性能：performance + core-web-vitals（先测后改：CLS <0.1 尤其重要——token/布局改动不得引入位移；LCP ≤2.5s、INP ≤200ms；改前改后数字进表）。
- 质量：web-quality-audit（全量审一遍）+ best-practices（现代 API/安全模式；不得留死代码）。
- 交前检测：impeccable（detect 全过才交付；未过的项列出并修到过）。
- 文案：humanizer（UI 文案有变动时才过一遍：按钮、空态、弹窗，去 AI 味；不许出现实现结构说明）。
- 执行纪律：karpathy-guidelines（先想再写、简单优先、最小改动）+ ponytail（能复用不重写——复用现有顶栏/底栏/卡片/弹窗实现，不另起一套）。
- 报告：i-have-adhd（结论 + 编号步骤 + 一个下一步）。
- 不调用：seo（工具页，不做公开页优化）、book-to-skill（没有书）、form-design（留言表单已落地，本提示词不改表单）、archify/diagram-design（不需要新架构图/流程图）、graphify/ponytail-audit（全站代码图是 super 第 0 阶段的事）、taste-skill（设计质量已由 ui-ux-pro-max + frontend-design 定）。

## 2. 设计 token 体系（源码级，不是散写数值）

- 全部 UI 数值走 CSS 变量：颜色、字阶、间距、圆角、阴影、动效曲线、玻璃参数（不透明度、模糊、饱和度、高光）；全站搜出散写数值并替换，交付时列出替换清单（哪几处、原来什么值、现在走哪个 token）。
- 抽查发现散写数值，该设计系统项按未落地计。
- token 改动不得改崩布局：改前改后 CLS 对照进表；字阶/间距动了，全站各页回归（webapp-testing）。

## 3. 玻璃材质系统（21:14 实测 FAIL，两档都没出来）

- 现状（21:14 实测）：浅色/深色两档下，面板基本实色，无透光/高光，50% 玻璃下也一样——材质感没出来。本提示词修的就是这个。
- 范围只限壳：顶栏、底栏、模块卡、面板、弹窗/抽屉；练习内容区（阅读文章、写作编辑器、听力句子、范文正文）保持全实色高对比，不得透。
- 材质标准：半透明 + 顶部高光（1–2px）+ saturate 1.4–1.8 + 1px 边框；文字永远实色；不堆超过 2 层半透明；不许两层以上嵌套圆角边框；左上汇总区只留一层。
- 弹窗/抽屉背景：变暗 + 轻模糊，背景文字必须可读；留言删除/清空弹窗已是干净变暗（保持），我的抽屉仍是强模糊（本提示词必改）；弹窗玻璃与卡片一致，不得纯白卡。
- 滑杆：玻璃滑杆加数字/档位标识；滑杆值 localStorage 持久化，CSS 变量实时生效；动效 200–300ms，hover +0.05–0.1、press −0.05，支持 prefers-reduced-motion。
- 两档都验：浅色/深色各附材质 before/after 对照（顶栏、卡片、弹窗三处），第一眼能看出透光/高光，不得还是实色。

## 4. 组件统一（源码级，不留重复实现）

- 顶栏、底栏、模块卡、弹窗/抽屉、题号导航、概览卡各只留一套实现；全站搜出重复实现并删掉，交付时列出删除清单（删了什么、原来在哪、现在统一到哪）。
- 动手前先列组件清单（现版顶栏/底栏/卡片/弹窗/导航/概览卡各有几套实现），按清单统一，不得边改边发现；删前列清单、删后全站回归（四张表里验）；删错导致功能丢失按未交付计。

## 5. 底栏（21:09 方向 + 22:51 单词页实证，原样接管）

- 只改 4 处，不动项数/顺序/标签/图标：① 内容区底部留白 = 底栏高度 + 安全区，末行永远不被底栏盖住（长页、短页都验，全站各页都验：首页/学习/留言/单词/考试页）；② 安全区用 env(safe-area-inset-bottom)，过 iPhone 小横条；③ 浮动胶囊化：四边留边距 + 圆角 + 阴影 + 玻璃（与顶栏一致）；④ 选中态保持（一主色 + 实色图标/粗体标签，未选中弱化），不另起一套状态系统。
- 触靶已够（4 项均分宽度），高度不动，不加中间大按钮、不去标签、不改动效。底栏是全站共享组件，本条一次改全站生效。
- 交付时附单词页底部截图证明末行完整可见（22:51 实证：底部“支持分隔符…”段落末行被盖）。

## 6. 量化 + 质化 + 价钱 + 交付

- 量化：CLS <0.1、LCP ≤2.5s、INP ≤200ms；对比度正文 ≥4.5:1、大字 ≥3:1，数值进表；触靶 ≥44px；零容忍：390px 横向溢出 0 处、末行被盖 0 处、死按钮 0 个；视口 390px 竖屏、手机横屏、iPad 各报表现 + 安全区；移动端项写“待真机验收”不得写成已通过。
- 质化：层级（动作最突出，状态次之，装饰最末）；区分（各页/各行一眼能区分）；质感（壳透光/高光，内容区实色）；文案（humanizer，不许实现结构说明）；动效（统一曲线，减动效支持）。
- 价钱（最便宜可用）：Hy3（0.00x 限时免费，若还在）→ Deepseek-V4.1-Flash（0.11x）；不要默认 Hy4 preview（0.29x）/ Ultimate（1.20x）/ Kimi-K3（1.62x）；送之前在模型选择器里复核当前费率（2026-10-20/21 的费率表可能已变）。
- 底线：localStorage 键 ielts.cbt.v1 + 数据结构不动；题目内容不动；评分算法不动；不加新练习模块；品牌 exactly “Y-IELTS”；内容区全实色；不加登录/服务器。
- 交付：表 1 每项落地表（要求项 / 改前 / 改后 / 自测结果 PASS/FAIL + 证据）+ 表 2 性能前后表 + 表 3 无障碍检查表 + 表 4 impeccable 检测表；报告格式：结论 + 编号步骤 + 一个下一步。
- 强制规则：每项只有两种结果——改了（附改前/改后对照：截图或实测数值）或没改（附技术原因 + 替代改动 + 下一版计划）；不得出现“已优化”“已提升”“已完善”等无证据词，每个这类词后面必须跟数字或截图，否则该项按未落地计；每页第一眼可见变化清单（首页、学习区、留言板、考试页各至少 3 处），缺了就是未交付；已落地项（手术①、翻转行、留言功能、提纲、分母、继续练习）只回归，不重做；日志只写真正落地的项。
- 约束（沿用）：不要点清空所有本地数据；不要提交任何新的阅读/听力试卷；不要点重新作答（只观察）；不要在写作编辑器里输入文字；结束时恢复主题明确浅色、口音美音 en-US、字号特大 4/4、玻璃滑杆 50%。
