# IELTS 机考模拟器 — 补丁提示词 v11 追踪补丁（只补 v11 验收未通过的 4 处 + 1 个误报回归，叠加在 v10、v11、v12 之上）

> 使用方法：在 WorkBuddy 同一个任务对话里分段粘贴（每段开头加一句“还没发完，先存着别动手”，最后一段发完再说“发完了，开始执行”）。
> 项目现状：纯前端静态站（源码在 /workspace/ielts-app/），数据存 localStorage。
> 背景：v11 验收结论是“没完全落地”。已经通过的不动：口音设置三模式共用、反馈卡片“再听一遍”三模式都有且点按出声、自动读开关拨动生效、词性 pill / Y-IELTS / 导出按钮 / 阅读计时器单框 / 反馈例句 / 真浅色回归全在。本版只修下面 5 项，不动题目逻辑、选项逻辑、计分逻辑、题库、本地存储，v12 的听力播放改法也不重做。
> 关键命名冲突先定死：v11 验收发现“发音”这个名字现在被口音选择器占了（美音 / 英音），所以三个模式里才没有一个统一叫“发音”的自动读开关。本版把口音选择器改名叫“口音”，把自动读开关统一叫“发音”，此后“发音”只指自动读开关，不再指口音。

---

## 一、发音开关统一命名与共享（补缺口 1）

1. 口音选择器改名：轮前那个美音 en-US / 英音 en-GB 选择器，文案改叫“口音”，仍三模式共用、切换后三模式同步、词库喇叭文案同步（如“朗读发音（英音）”可保留，因其指口音值，不是指开关）；
2. 自动读开关统一：把拼写默写现有的“新题自动朗读”复选框改名、改样式，变成与其他两模式完全相同的“发音”开关；三模式里都必须出现一个文案 exactly 为“发音”的开关，不许只剩复选框；
3. 语义与共享：开关开 = 新题自动朗读，关 = 只手动点喇叭才读，默认开；开关状态三模式共用（一个模式里关掉，其他模式同步关掉），且与 v12 的听力共用同一状态（关掉发音时听力也不自动读，只手动点播放才读）；
4. 位置样式一致：开关在三模式设置区的同一位置、同一尺寸、同一开关样式（不是一处是开关、一处是复选框）。

## 二、喇叭按钮统一为同一组件（补缺口 2）

1. 三模式题面使用同一个喇叭组件：同一位置（题目旁同一侧）、同一尺寸、同一图标、同一文案（如“朗读”）、同一边框/颜色样式；不许英译汉是小蓝按钮、默写是居中大白喇叭；
2. 默写模式的改法：把居中大白喇叭换成上述同一组件；“点喇叭可无限次重听（只读单词）”这句说明不许再长在按钮上，改为按钮下方一行小字提示；无限重听功能本身保留；
3. 播放状态文字统一：播放中显示“播放中…”，失败显示“朗读失败，点我重试”，位置与样式三模式一致，不许只用颜色变化表示状态。

## 三、答错重读三模式一致（补缺口 3）

1. 发音开关开时，答错后在显示正确答案的同时，把该正确单词自动再读一遍——三模式都要做到，不许只有默写做到；
2. 验收用例（照着测，不许换词蒙混）：英译汉答错 advocate、汉译英答错 inevitable（正确词 analyse，题面是“分析”）、拼写默写答错 coherenx（正确词 coherent，后者此前已通过，作为对照）；
3. 发音开关关时不强制自动重读，但反馈卡片的“再听一遍”必须可用（此前三模式已有，保留）。

## 四、汉译英补齐防剧透喇叭与答后自动读（补缺口 4，最多的一项）

1. 答前置灰喇叭：汉译英题面必须有与另两模式同一组件的喇叭按钮，答前置灰（disabled，不可点、不发声——防剧透本身是对的，保留），旁边注明“答后可听”；不许答前完全没有喇叭；
2. 答后自动读：答后该喇叭恢复可用；发音开关开时，反馈出现的同时自动读正确英文词一遍（与英译汉、默写一致）；
3. 答后状态 pill：汉译英播放时必须出现与其他模式同一位置、同一文案、同一样式的“播放中…”小 pill；此前汉译英任何视图里一次都没出现过，本版必须有；
4. 反馈“再听一遍”保留：此前汉译英反馈卡片的“再听一遍”（带例句 + 🔊，点按读正确词）已通过，保留不动。

## 五、英音误报回归修复（验收顺带发现，不许留到下版）

1. 现象：英音下默写词一开始挂着“当前设备暂无可用语音”描述，但手动点按照样出声——这是误报，不是真无语音；
2. 改法：不许凭首次 getVoices 快照就下“暂无可用语音”结论；必须等 voiceschanged、按 v11 的延迟重试（如 3 次 × 300ms）后再判断；只有重试后仍为空，或某次 speak 实际失败时，才显示“当前设备暂无可用语音”/“朗读失败，点我重试”；
3. 误报清除：一次手动播放成功后，之前挂着的“暂无可用语音”描述必须立即清除；英音匹配仍精确匹配 en-GB，匹配不到回退任意 en 语音并标明实际语音。

## 七、防假落地规则（沿用 v10 第 0 部分数值自证）

1. 喇叭组件与发音开关必须报实测数值：三模式的喇叭按钮 getBoundingClientRect 宽、高、与题目的相对位置必须一致（允许 1–2px 舍入差，超出即未统一）；开关同理；
2. 代码存在类（“发音”开关、置灰喇叭、“答后可听”、“播放中…”pill、误报判断分支）附源码 grep 文件名 + 行号 + 片段；只写“已统一”不算数；
3. 发布后必须用无痕窗口 / 新标签重新打开验证一遍，排除旧缓存假象；发布时更新静态资源指纹或 service worker 缓存版本；
4. 只动上述 5 项：不许动其他功能逻辑、数据结构、题库、本地存储；老数据必须完好；做不了的必须明说原因和替代方案，不许报“已完成”。
