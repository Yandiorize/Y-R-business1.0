# Y-IELTS UI 优化（按 WB 综合包执行，只做 UI，不动功能和数据）

按综合包执行：frontend-design + web-development + ui-animation + web-design-reviewer + webapp-testing，全部技能都用上，只做下面列出的 UI 项，其他一律不动。

## 硬约束（高于所有通用技能，违反即不合格）
- 站点头部品牌必须是 `Y-IELTS`，不要改成别的名。
- 纯浏览器本地存储、无登录，不要加账号、后端、收费墙。
- 不改题库、不改计分算法、不改已有用户数据、不改 localStorage key（ielts.cbt.v1）和数据结构。
- 手机优先：先保证 iPhone Safari 390px 下可用，再谈桌面宽屏。
- 一次任务只做下面列出的项，任务外的新功能、新模块一律不加。

## UI 优化项（全部）
1. frontend-design：每屏只有一个主意图、一个视觉重点；全站颜色不超过一套主色 + 一套辅助色，间距、圆角、字号、图标风格统一；主操作一眼可见，次要操作弱化；删掉既不帮助理解、也不帮助决策、也不帮助完成的元素；最后做一次简化审计，删重复卡片、删 competing 的颜色、删含糊的按钮。不要为了“现代化”改框架、不要引入构建工具。
2. web-development：先读现有文件结构再动手，文件归属和命名和现有文件一致，不在根目录乱放临时文件，不改现有 JS 文件的分工；改动可回退，一次只做一小批。
3. ui-animation：只用 CSS，只用 transform / opacity 做动效，不要用会触发布局重排的属性；时长 200–300ms，克制，不要满屏飘、不要无限循环抢注意力；支持 prefers-reduced-motion，用户关动效就要真的停；动效不能遮内容、不能挡按钮，底部导航、悬浮按钮必须给内容留出底部 padding + iPhone 安全区，不能盖住“开始练习”、最后一行、面板底边。
4. web-design-reviewer：按 Blockers 先行自查——按钮点不动、内容被导航盖住、交卷/计分/历史算错、数据被清空、手机端布局溢出是 Blocker；层级不清、间距不统一、文案含糊、空状态缺失是 Suggestion；个别圆角、色值、字号微差是 Nit。必查：手机 390px 下不横向溢出，字号最大档下文字和标签不重叠；浅色 / 深色 / 跟随系统三种模式都可读；所有改动过的按钮、筛选、切换、交卷、返回路径都真实点过，不只看代码；文字对比度够，按钮可聚焦、可键盘操作，图片和图标有可读的文字说明。
5. webapp-testing：改完按真实路径走一遍再发布：首页 → 每个改动过的模块 → 交卷 / 结果 → 历史 → 返回首页。报告格式：每项写 PASS / FAIL / 未验证，并写你实际看到的现象，不要写推测；失败项写复现步骤和影响面；浏览器语音、音频这类在当前环境测不准的，写“现象 only，需真机复测”，不要直接判产品 bug；发布前清理测试数据，测试用的单词、记录、草稿要清掉，恢复到用户原来的数据状态。

## 验收
- 发布前按上面第 5 节逐项点一遍再发布，报告里每项都要有 PASS / FAIL / 未验证 + 实际现象。
- 不确定的地方宁可不动、写进报告，也不要编一个“看起来对”的结果。
