## 第 0 部分：数值自证总规则（本版新增，凌驾于一切“已完成”表述之上）

背景：外部验收方无法读取元素的包围盒与计算样式（只能看到文字树、没有开发者工具），所以布局与玻璃类的数值**只能由你（有源码与浏览器环境的 agent）在本轮实测并上报**。没有数值的汇报视为未完成。

1. 布局类（宽度、高度、对齐、间距）：每一项必须附改前与改后两组实测数值——用 getBoundingClientRect 量宽度、高度、上下边缘 y 坐标、间距，用视口宽度算 vw 占比；只写“已改到 96vw / 已对齐 / 看着正常”不算数；
2. 玻璃类（透明度、模糊）：每一项必须附 getComputedStyle 实测值——背景色 alpha 值、backdrop-filter 的 blur 值、saturate 是否存在；改前与改后两组数对照；
3. 代码存在类（滑杆、失败文字）：必须附源码 grep 结果——文件名 + 行号 + 关键代码片段；只写“已实现”不算数；
4. 窄屏类（≤430px）：必须在 390px 宽度下实测（浏览器设备模拟或响应式断点）并汇报数值：底部栏高度、按钮尺寸、触点大小、安全区关系、窄屏顶栏对齐数值；没有窄屏实测的项视为未完成；
5. 触发类（失败文字）：必须实际触发一次并截图/录屏佐证；触发不了的，必须用代码 grep 证明逻辑存在（文件名 + 行号），并写清触发条件；
6. 汇报表必须有一列“实测数值”，逐项填 px / alpha / blur / 行号；空着数值的项按未完成计。

## 本版必做 7 项（逐项验收，全部附数值）

### 1. 玻璃透明度滑杆（iOS 27 标志功能，仍缺失）

- 现状：主题按钮只循环切换（浅色→深色→跟随系统→浅色），不开任何菜单；各模块都没有设置页、设置抽屉、外观入口；全站找不到任何“玻璃透明度”滑杆。
- 改法：在主题设置区加一个“玻璃透明度”滑杆，连续可调：从“清晰”（接近实色）到“通透”（高度透明），默认停在中间档；拖动时全站玻璃透明度跟手变化（用 CSS 变量统一控制，如 --glass-opacity，铬层与容器层按比例联动）；选择存 localStorage，刷新、切换主题后保持。
- 数值自证：汇报滑杆所在位置（哪个入口、哪个面板）+ 默认档位 + 拖动两端实测的铬层/容器层 alpha 值 + 刷新后保持的证据；源码 grep 附文件名 + 行号。

### 2. 顶栏三按钮对齐（回归：清空矮一截）

- 现状：三个按钮同一行、基线基本平、间距均匀、没挤压，但清空比 A+字号、主题矮一截且无边框——三个高度和上下边缘对不上，歪的就是中间这个清空。
- 改法：三个按钮统一样式、同高（44px 级）、同一基线、同一边框样式；图标与文字在按钮内居中；空间不足时标题文字省略号截断，不挤压按钮。
- 数值自证：改前与改后各附三按钮的高度 px、上下边缘 y 坐标、间距 px；三者高度差必须为 0。

### 3. 阅读容器宽度（精确数值未证实）

- 现状：桌面端看着接近全屏宽、高度顶满，但 96vw 与 12–16px 边距从未量出数值。
- 改法：内容容器宽度改为 96vw 以上、左右边距 12–16px；超宽屏可设 1600px 上限；手机（≤430px）布局不动。
- 数值自证：附视口宽度 px、容器宽度 px、vw 占比、左右边距各 px；改后必须满足 96vw 以上且边距 12–16px。

### 4. 玻璃默认透明度数值（精确数值未证实）

- 现状：默认看着鲜艳、文字高对比，但铬层/容器层透明度与 saturate 从未量出数值。
- 改法：默认档铬层约 0.55、容器层约 0.75，saturate 1.4–1.8；滑杆（第 1 项）联动两档。
- 数值自证：附顶栏（铬层）与内容卡片（容器层）getComputedStyle 的背景色 alpha 值、backdrop-filter blur 值、saturate 值；改后必须接近 0.55 / 0.75。

### 5. 长文区透明度数值（精确数值未证实）

- 现状：阅读、范文正文看着锐利清晰，但容器透明度 ≥0.75 从未量出数值。
- 改法：长文区（阅读文章、范文正文、写作编辑区）默认档容器透明度不低于 0.75；文字永远纯色。
- 数值自证：附阅读文章卡片与范文正文卡片的背景色 alpha 值；改后必须 ≥0.75。

### 6. 窄屏 390px 数值（桌面端无法验证，必须由你实测）

- 现状：底部标签栏元素在 DOM 里存在（主导航：阅读 / 听力 / 写作 / 单词 / 范文），但桌面宽屏下不显示为栏；窄屏高度、触点、安全区、窄屏顶栏对齐从未量出数值。
- 改法（沿用 v9 D 部分）：底部标签栏已改矮、五个按钮已放大（图标与文字各放大一档约 10%–15%，等宽均匀分布，选中态不变）；栏体透明液态玻璃（见 iOS 27 玻璃章）；底部安全区 padding-bottom: env(safe-area-inset-bottom) 保留，不许 Home 指示条遮挡。
- 数值自证：在 390px 宽度下实测并汇报：栏体高度 px、五个按钮尺寸 px、触点 px（必须 ≥40px）、安全区关系、窄屏顶栏三按钮高度/边缘数值。

### 7. “朗读失败”文字存在性（从未触发）

- 现状：历次播放全部成功，“朗读失败，点我重试”从未出现；页面文字搜索也搜不到（但此类搜索曾漏过小字状态）；代码层因外部无法打开脚本文件而未知。
- 改法：发音失败时按钮旁必须显示“朗读失败，点我重试”，喇叭按钮始终可手动点；不许静默没声。
- 数值自证（二选一）：实际触发一次并佐证（触发条件 + 显示效果）；或源码 grep 附文件名 + 行号 + 关键代码片段，证明失败分支存在且文案正是这句。

## iOS 27 玻璃章（参数以本份为准，取代玻璃综合版与极端强化版）

- 透明度滑杆：见必做 1（默认中间档、实时生效、刷新保持、两端各实测）。
- 默认渲染：高对比 + 更鲜艳（见必做 4）；默认档不许拉到最透。
- 边缘与折射：1px 细边框 + 顶部 1–2px 高光边；图标、按钮、卡片多层结构（底色层 + 玻璃层 + 高光层），层间分离可见；玻璃下内容 backdrop blur + 亮度/饱和微调模拟轻微折射，栏体边缘折射延续到边缘；图标颜色保持本色，不被背景带偏。
- 纵深分离：背景最糊、卡片次之、弹窗与悬浮栏最实但仍透；弹窗出现时下方页面一层极淡遮罩 + 模糊。
- 栏体形态：顶栏、工具条、底部标签栏悬浮胶囊式（四周留边、大圆角、浮在内容上）；改矮 + 按钮放大同步保留。
- 深浅主题与动效：浅色白底玻璃 + 深色字、深色深底玻璃 + 近白字；切换、拖动过渡 200–300ms；按钮悬停透明度 +0.05–0.1、按下 −0.05；遵守 prefers-reduced-motion。
- 可读性底线：文字永远纯色；长文区默认档 ≥0.75（见必做 5）；同一区域不许两层以上半透明叠加；玻璃栏下方内容经过时栏内图标文字仍可辨认；滑杆拉到“清晰”端时全站接近实色、处处可读。

## D 部分：手机版专项（≤430px 宽度，桌面布局不要动，用媒体查询隔离）

1. 安全区：固定/吸顶顶栏加 padding-top: env(safe-area-inset-top)（constant() 兜底），底部标签栏加 padding-bottom: env(safe-area-inset-bottom)；不许写死像素值；灵动岛、刘海、Home 指示条都不能遮挡按钮；
2. 顶栏单行化：logo + 标题在左、按钮组在右，一行放完，不换行、不遮挡、不裁切；
3. 全站禁止横向滚动：任何页面在 390px 宽下不得出现左右滑动，超宽元素自己内部处理，不许撑破页面；
4. 阅读：左右分栏改上下堆叠或“文章 / 题目”切换标签，不要把两栏硬挤在一起；计时器和交卷按钮始终可见可点；40 题题号格完整显示、每格可点；划词高亮工具条不超出屏幕边缘、不被吸顶顶栏盖住（位置做边界钳制）；
5. 写作：题目区、编辑区、统计面板上下堆叠；编辑区高度够打字，统计数字不挤成一团；工具条换行分组，但计时器、开始、交卷等关键按钮换行后仍完整可见；
6. 单词：卡片与按钮全宽排列，点击目标不小于 40px；导入文本框、筛选、列表、练习行在窄屏不溢出；
7. 范文：列表卡片单列，详情正文行宽适配手机，不用横向滚动；详情头按钮行换行；
8. 弹窗：一律居中、四周留边距，按钮可点，不许超屏；
9. 固定栏（顶栏 / 底部标签栏）不得遮挡正文内容：给页面加足上下滚动留白；
10. 手机端模块工具条取消吸顶或压成一行，只保留主顶栏吸顶（吸顶换行成 2–3 行会吃掉 200px 以上高度）。

### D-增补：实测量化清单（逐条达标才算过，数值见第 0 部分）

1. 顶栏单行内容总宽约 1260px，其中模块导航标签就超过 440px——手机上必须有移动端方案（导航进底部标签栏或横向滚动条），计时器、交卷、设置按钮不许被挤出屏幕；
2. 阅读题号格每格只有约 33×30px、角标小旗约 12px，远低于 40px 点击标准——手机端题号格放大到不小于 40×40（可减少每行列数或让题号区独立滚动），小旗热区同步放大；
3. 阅读左右两栏是固定高度、各自内部滚动——手机堆叠时不许保留双内滚：改成整页滚动，文章与题目自然衔接（或切换标签），不能出现两个小矮窗格；
4. 写作工具条单行约 1200px、单词练习行约 800px、范文详情头约 480px、词库工具行约 480px——手机上一律允许换行分组，但关键按钮换行后仍完整可见；
5. 确认弹窗桌面宽约 420px，比 390px 屏幕还宽——所有弹窗加 max-width: calc(100vw - 32px)，按钮高度保持 ≥44px；
6. 次要文字约 12px（题号数字、词数统计等）手机上偏小：手机端辅助文字不小于 12px 且保证对比度，正文维持约 15px 不动。

## E 部分：自查补缺（逐项先报状态：已有 / 半成品 / 没有，缺哪补哪）

## 全局约束（必须遵守）

1. 每完成一项先自己实际点击/操作验证真的生效，再做下一项；禁止只改外观不验逻辑，禁止留下“有入口但点了没反应”的半成品；
